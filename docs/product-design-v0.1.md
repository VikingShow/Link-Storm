# Link Storm 产品设计文档 v0.1

产品名：灵机一动 Link Storm  
方向：前沿情报与本地机会联动的行动型信息产品  
目标端：鸿蒙 App 优先，后续可扩展到 Web、桌面卡片、企业版

## 1. 产品一句话

Link Storm 帮助创业者、开发者、投资人、企业管理者从前沿新闻、产业信号和本地活动中发现真正值得行动的机会，并把“知道”转化为“学习、连接、参加、实践”。

## 2. 背景判断

当前市场上存在两类成熟产品：

1. 资讯类产品：36 氪、虎嗅、Techmeme、Feedly、Yahoo News、Particle 等。
2. 活动类产品：活动行、Meetup、Luma、Eventbrite 等。

它们分别解决了“看资讯”和“找活动”的问题，但多数产品没有把“行业变化”和“现实行动”连接起来。

Link Storm 的机会不在于做一个更大的新闻流，而在于做一个更克制、更高密度、更能促成行动的机会雷达。

## 3. 核心用户

### 3.1 第一批目标用户

1. 创业者：想知道新趋势、新政策、新融资、新资源。
2. 开发者：关注 AI、机器人、开发工具、技术沙龙和项目机会。
3. 投资人/FA/产业研究者：关注公司动态、融资信号、行业事件。
4. 企业管理者/业务负责人：关注行业变化、客户线索、合作机会。
5. 城市产业从业者：关注园区活动、产业论坛、政策宣讲、企业开放日。

### 3.2 用户核心动机

用户不是单纯想刷新闻，而是想更快回答：

1. 最近有什么重要变化？
2. 这个变化跟我有什么关系？
3. 我现在能做什么？
4. 附近有没有可以参加、学习、认识人的机会？

## 4. 产品原则

### 4.1 少而硬

默认不做无限信息流。首页信息必须经过筛选，每天只给少量高价值内容。

### 4.2 可解释

每条推荐都要告诉用户：为什么推荐、为什么重要、下一步可以做什么。

### 4.3 知而行之

用户可以继续探索，但系统要在适当位置主动停止用户的无效刷屏，引导用户学习、实践、收藏、加入日程或参加活动。

### 4.4 本地机会优先

同样的信息，如果能连接到用户所在城市附近的活动、组织、园区、论坛、开放日，优先推荐。

### 4.5 不做泛娱乐信息流

不追求停留时长最大化。产品目标是提升有效决策和行动转化。

## 5. MVP 范围

### 5.1 首批领域

建议 MVP 只覆盖 3 个领域：

1. AI / 大模型 / 智能体
2. 机器人 / 智能制造
3. 跨境出海 / 增长 / 企业服务

原因：这三个方向有高频新闻、高价值活动、明确人群、商业化潜力。

### 5.2 首批城市

建议 MVP 只覆盖 5 个城市：

1. 深圳
2. 上海
3. 北京
4. 杭州
5. 广州

原因：活动密度高，产业集群明显，用户更容易从线下机会中获得价值。

### 5.3 MVP 不做的事情

1. 不做全网新闻客户端。
2. 不做用户发帖社区。
3. 不做复杂社交关系链。
4. 不自建活动报名系统，第一阶段跳转原报名链接。
5. 不做完全自动化内容发布，先保留人工校准能力。

## 6. 核心功能结构

### 6.1 今日情报

每天给用户 5 到 8 条高价值情报。

每条情报结构：

```text
标题
一句话结论
关键信号
为什么重要
影响对象
下一步建议
相关活动
来源链接
```

示例：

```text
标题：具身智能供应链在华东继续升温
一句话结论：机器人公司和核心零部件企业正在从概念验证进入供应链落地阶段。
关键信号：融资、园区政策、头部企业开放生态合作。
为什么重要：产业机会开始从模型和样机转向制造、集成和场景交付。
影响对象：机器人创业者、制造企业、投资人、开发者。
下一步建议：关注本周上海和苏州的机器人产业活动。
相关活动：上海机器人开发者沙龙、苏州智能制造开放日。
```

### 6.2 继续探索

在今日情报之后，用户可以选择继续看更多内容。

继续探索不是无限滚动，而是分段式探索：

1. 第一段：今日精选，5 到 8 条。
2. 第二段：更多相关，最多 10 条。
3. 第三段：深挖一个主题，最多 5 条。
4. 第四段：进入“知而行之”停止页。

这样既满足用户“我想多了解一点”的需求，也避免变成低质量信息流。

### 6.3 知而行之

“知而行之”是产品的关键设计。

当用户连续浏览达到一定阈值时，系统不继续无止境推荐，而是展示一个行动引导页。

触发条件可以是：

1. 用户连续浏览 20 条内容。
2. 用户在同一主题停留超过 8 分钟。
3. 用户阅读了 3 条以上同主题内容但没有收藏、加入日程、打开来源或报名活动。
4. 用户主动点击“今天看到这里”。

页面内容：

```text
知而行之

你已经了解了足够多关于「AI 智能体」的信号。
现在更值得做的是选一个小行动。

建议行动：
1. 学习：阅读一篇入门材料或官方文档。
2. 实践：用一个工具完成一次小实验。
3. 连接：参加附近相关活动。
4. 沉淀：把今天的 3 条关键信号收藏成主题笔记。
```

可操作按钮：

1. 加入学习清单
2. 查看附近活动
3. 生成实践任务
4. 收藏今日情报
5. 今天到这里

### 6.4 附近活动

根据用户城市、兴趣领域、时间偏好推荐活动。

活动类型：

1. 行业论坛
2. 企业开放日
3. 技术沙龙
4. Demo Day
5. 投融资路演
6. 园区政策宣讲
7. 高校/协会活动
8. 开发者活动

活动卡片字段：

```text
活动标题
时间
地点
城市
主办方
适合人群
推荐理由
活动质量分
报名链接
加入日程
提醒设置
```

活动排序优先级：

```text
领域匹配度 > 城市距离 > 时间临近度 > 主办方可信度 > 嘉宾含金量 > 历史口碑
```

### 6.5 机会日历

把用户收藏或系统推荐的活动展示成日程。

视图：

1. 今天
2. 本周
3. 本月
4. 主题视图

日程状态：

1. 感兴趣
2. 已加入日程
3. 已报名
4. 已参加
5. 已错过

### 6.6 主题雷达

用户选择关注主题，系统持续追踪。

MVP 主题：

1. AI 智能体
2. AI 应用出海
3. 机器人
4. 智能制造
5. 企业服务
6. 跨境电商
7. 投融资
8. 政策/园区

每个主题页包含：

1. 今日信号
2. 关键公司
3. 近期活动
4. 推荐学习材料
5. 可实践任务

### 6.7 灵感捕捉

用户在阅读情报、查看活动或进入知而行之页面时，应该能随时记录自己的想法。

这个能力不是单独的笔记 App，而是嵌入 Link Storm 的“边看边记”功能。记录内容会和当前情报、活动、主题、城市、时间自动关联，后续可以沉淀成用户记忆、行动清单或主题笔记。

不同设备默认打开不同捕捉方式：

```text
手机：优先调起语音记录
平板：优先调起写字板
二合一/PC：优先调起文档编辑器
```

核心原则：

1. 三端使用同一个数据模型。
2. 只根据设备形态和窗口尺寸改变默认交互。
3. 用户可以手动切换语音、手写、文字三种模式。
4. 第一版先保存原始记录，后续再做 AI 加工。

#### 手机端：语音想法

适合单手、通勤、走路、活动现场。

交互：

```text
长按情报卡片上的麦克风按钮
-> 开始录音
-> 松手保存
-> 自动关联当前内容
-> 后台尝试转文字
```

第一版即使没有语音转文字，也必须保存音频文件和上下文。

保存内容：

```text
音频文件
录音时长
关联情报/活动/主题
录音时间
城市
转写状态
```

#### 平板端：写字板

适合用户用手写笔、触控笔或手指快速写想法。

交互：

```text
点击笔按钮
-> 右侧或底部打开写字板
-> 用户手写
-> 自动保存笔迹
-> 可补充文字标题
```

第一版保存笔迹矢量数据和预览图，不强制做手写识别。

保存内容：

```text
笔迹路径
预览图片
关联情报/活动/主题
创建时间
标题
```

#### 二合一/PC 端：文档笔记

适合用户深入思考、整理成段落、形成行动计划。

交互：

```text
点击文档按钮
-> 打开右侧文档面板
-> 支持标题、正文、清单
-> 可一键插入当前情报摘要和来源
-> 保存为主题笔记
```

保存内容：

```text
标题
正文
清单
引用的情报/活动
创建时间
更新时间
```

#### 后续 AI 加工

当语音转文字、手写识别或文档整理能力可用后，可以增加：

1. 语音转文字。
2. 手写转文字。
3. 自动生成标题。
4. 自动提炼行动项。
5. 把多条想法合并为主题笔记。
6. 把行动项加入知而行之任务。

示例：

```text
用户语音：这个机器人供应链活动可以去看看，顺便问一下减速器国产替代的情况。

加工后：
标题：机器人供应链活动跟进
行动项：报名上海机器人供应链活动
问题：现场了解减速器国产替代进展
关联主题：机器人、智能制造
```

## 7. 页面设计

### 7.1 底部导航

建议 4 个主 Tab：

1. 情报
2. 活动
3. 日程
4. 我的

### 7.2 情报页

页面结构：

```text
顶部：城市 + 今日日期 + 兴趣入口
模块一：今日 5 条必看
模块二：和你相关的本地机会
模块三：继续探索
模块四：知而行之
```

关键交互：

1. 左右滑切换情报卡。
2. 上滑看详情。
3. 点击“为什么推荐”查看推荐解释。
4. 点击“下一步”进入学习、实践或活动。

### 7.3 活动页

页面结构：

```text
顶部：城市选择 + 时间筛选 + 领域筛选
模块一：本周值得去
模块二：按日期排列
模块三：按主题排列
模块四：线上活动
```

筛选项：

1. 今天
2. 本周
3. 本月
4. 免费
5. 线上
6. 线下
7. 距离优先
8. 质量优先

### 7.4 日程页

页面结构：

```text
顶部：本周时间轴
模块一：已加入日程
模块二：系统建议提醒
模块三：错过后回顾
```

错过后回顾很重要。用户错过活动后，系统可以提供：

1. 活动资料链接
2. 主办方后续活动
3. 同主题下一个活动

### 7.5 我的页

包含：

1. 兴趣主题
2. 所在城市
3. 推送设置
4. 收藏
5. 阅读历史
6. 隐私设置

## 8. 推荐与评分机制

### 8.1 情报价值评分

```text
情报价值分 =
来源可信度
+ 信息密度
+ 新颖性
+ 行业影响
+ 可行动性
+ 与用户兴趣匹配度
+ 与用户城市/活动关联度
- 重复度
- 营销味
- 标题党概率
- 软文概率
```

### 8.2 活动质量评分

```text
活动质量分 =
主办方可信度
+ 议题匹配度
+ 嘉宾/机构含金量
+ 时间地点明确度
+ 报名链路完整度
+ 历史活动质量
+ 与近期情报关联度
- 纯营销课概率
- 虚假/低质活动风险
- 信息缺失程度
```

### 8.3 知而行之触发评分

```text
停止触发分 =
连续阅读数量
+ 同主题重复阅读数量
+ 停留时长
+ 无行动行为次数
- 收藏次数
- 加入日程次数
- 打开来源次数
- 报名点击次数
```

当停止触发分超过阈值时，显示“知而行之”。

## 10. 数据处理链路

```text
采集内容
-> 清洗正文
-> 提取实体：公司、城市、行业、时间、地点、人物、机构
-> 去重与事件聚合
-> 分类打标签
-> 摘要与结构化改写
-> 价值评分
-> 活动关联
-> 人工审核
-> 分发给用户
```

事件聚合很重要。同一件事可能有多篇文章，用户应该看到的是一个“事件”，不是 10 条重复新闻。

## 11. 推送策略

### 11.1 默认推送

1. 每天早上 8:30 推送今日情报。
2. 活动前一天晚上 8:00 提醒。
3. 活动前 2 小时提醒。

### 11.2 即时推送

只在高价值事件出现时触发，例如：

1. 用户高度关注主题出现重大变化。
2. 用户所在城市出现强匹配活动。
3. 用户收藏主题出现报名截止提醒。

### 11.3 防打扰机制

1. 每天最多 2 条主动推送。
2. 低价值内容不推送。
3. 用户可设置免打扰时间。
4. 用户可以选择“只推活动提醒”。

## 12. 鸿蒙端设计重点

### 12.1 适合鸿蒙的能力

1. 原生推送：用于日报和活动提醒。
2. 定位授权：只使用城市级别定位，降低隐私压力。
3. 日历能力：活动加入系统日历。
4. 卡片能力：展示今日情报和本周活动。
5. ArkUI：实现卡片式情报、时间线日程、筛选面板。

### 12.2 隐私原则

1. 默认只保存城市，不保存精确坐标。
2. 精确定位只在“附近活动”场景中临时使用。
3. 用户可以手动选择城市。
4. 清楚展示推荐依据。

1. 情报首页

4. 知而行之停止页

目标：可以人工录入和审核内容。

1. 内容表

3. 主题表

5. 管理后台

目标：降低人工成本。

交付：

1. RSS/网页采集
2. 正文清洗
3. AI 摘要

5. 初步评分

目标：形成真实使用闭环。

交付：

1. 用户兴趣画像
2. 城市活动推荐
3. 鸿蒙推送
4. 日程提醒
5. 行为反馈优化

## 15. 关键指标

### 15.1 内容质量指标

1. 情报收藏率
2. 来源打开率
3. “不感兴趣”比例
4. 单条情报平均阅读完成率
5. 用户主动继续探索比例

### 15.2 行动转化指标

1. 活动加入日程率
2. 报名链接点击率
3. 知而行之页面行动点击率
4. 用户每周收藏主题数
5. 活动提醒后的回访率

### 15.3 留存指标

1. D1 留存
2. D7 留存
3. 每周打开天数
4. 每周有效行动次数

这里的“有效行动”包括收藏、打开来源、加入日程、报名点击、完成实践任务。

## 16. 风险与应对

### 16.1 内容质量不稳定

应对：

1. MVP 保留人工审核。
2. 建立来源白名单。
3. 对低质量来源降权。
4. 通过用户反馈训练评分规则。

### 16.2 活动数据不完整

应对：

1. 先覆盖少数城市。
2. 优先抓高质量平台和主办方官网。
3. 缺少时间、地点、报名链接的活动不推荐。

### 16.3 退化成新闻流

应对：

1. 限制首页数量。
2. 分段式继续探索。
3. 加入知而行之停止页。
4. 用行动指标替代单纯停留时长。

### 16.4 推荐不准

应对：

1. 冷启动用城市、角色、主题三项信息。
2. 每条推荐提供“不感兴趣”和“更多类似”。
3. 展示推荐理由，方便用户理解和校正。

## 17. 建议的第一版体验闭环

```text
用户选择城市和兴趣
-> 进入今日情报
-> 看到 5 条高价值情报
-> 点击某条查看为什么重要
-> 系统推荐相关本地活动
-> 用户加入日程
-> 活动前收到提醒
-> 活动后系统推荐复盘资料或下一个相关活动
```

## 18. 下一步

建议下一步先做两个交付：

1. 鸿蒙 App 原型：用假数据跑通“情报 -> 活动 -> 日程 -> 知而行之”。
2. 内容后台原型：支持人工录入情报和活动，给前端提供真实接口。

如果只做一个，优先做鸿蒙 App 原型。因为产品关键假设是交互体验，而不是采集能力。
