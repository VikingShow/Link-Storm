# LinkStorm UI/UX 优化方案

## 一、核心问题诊断

### 1.1 设备适配完全失效

| 问题 | 根因 | 文件:行 |
|------|------|---------|
| 平板显示手机模式 | `layoutMode` 只有 `compact`/`desktop`，680-1100vp 映射到 `compact` | Index.ets:690-701 |
| 初始检测用硬编码宽度 | `applyDefaultMode(CANVAS_WIDTH=900)` 而非实际屏幕宽度 | Index.ets:109 |
| 没有平板模式提示 | `deviceHint()` 只返回 `'手机模式'`/`'桌面模式'` | Index.ets:683-688 |
| Tabs 只有两档 | `barPosition` 只判断 compact vs desktop | Index.ets:119 |
| List 列数只有两档 | `lanes` 只给 desktop 多列，平板单列 | Index.ets:387 |
| 断点阈值不对齐官方 | 680/1100 vs 官方 600/840 | Index.ets:45-46 |

**HarmonyOS 官方断点标准**：
| 断点 | vp范围 | 典型设备 |
|------|--------|---------|
| sm | [320, 600) | 手机竖屏、折叠屏折叠 |
| md | [600, 840) | 手机横屏、小平板、折叠屏展开 |
| lg | [840, +∞) | 平板、PC |

**官方推荐**：
- `Navigation.mode(NavigationMode.Auto)` — ≥600vp 自动 Split，<600vp Stack
- `GridRow.onBreakpointChange` 检测断点（但 `onAreaChange` 也能工作，保留当前方式）
- 不建议用 `deviceType`/`isFoldable` 控制布局，用断点

**修复方案**：
- 断点阈值改为官方标准：`600` / `840`
- 三档 `layoutMode`：`'compact'`(<600) / `'medium'`(600-840) / `'desktop'`(≥840)
- 保留 `onAreaChange` 方式（当前已用，无需引入 GridRow 包装）
- `applyDefaultMode` 仅首次设置 `activeType`，不覆盖用户手动选择

### 1.2 默认捕捉类型错误

| 问题 | 根因 | 文件:行 |
|------|------|---------|
| 手机默认显示文档模式 | `@State activeType = IdeaType.DOCUMENT` | Index.ets:53 |
| 旋转设备时覆盖用户选择 | `applyDefaultMode` 每次都覆盖 `activeType` | Index.ets:690-701 |
| 680-1100 默认 HANDWRITING 不合理 | 平板默认手写？ | Index.ets:695 |

**修复方案**：
- `activeType` 初始值改为 `IdeaType.AUDIO`（手机最自然的捕捉方式）
- `applyDefaultMode` 添加 `isFirstDetection` 标志，仅首次设置 `activeType`
- medium 档默认也用 `AUDIO`（平板也常录音），desktop 用 `DOCUMENT`

### 1.3 录音 UI 不专业

| 问题 | 根因 | 文件:行 |
|------|------|---------|
| 5个按钮横排 | `AudioEditor` 用 `Row({space:8})` 放 start/pause/resume/stop/cancel | CaptureEditorComponent.ets:98-139 |
| 无录制视觉反馈 | `Progress({value:0})` 硬编码 0，永不更新 | CaptureEditorComponent.ets:92-95 |
| 无状态动画 | 按钮只是 enable/disable | CaptureEditorComponent.ets:98-139 |

**业界标准**（Apple Voice Memos / Otter.ai / WhatsApp）：
- **大圆钮** 64vp，状态驱动 icon/颜色/动画
- idle: 填充圆 + 🎤 → 点击开始
- recording: 填充圆 + ❚❚ + 脉冲动画 → 点击暂停
- paused: 描边圆 + ▶ → 点击继续
- 保存/取消为次要按钮，仅 recording/paused 可见
- 实时计时器 MM:SS

### 1.4 色彩体系缺陷

| 问题 | 根因 |
|------|------|
| `surface_secondary` ≈ `surface_primary` | light: `#FBFCFD` vs `#FFFFFF`，不可区分 |
| `text_secondary` ≈ `text_tertiary` | light: `#697386` vs `#667085` |
| 手写笔画暗黑模式不可见 | `STROKE_COLOR = '#111827'` 硬编码 | CaptureEditorComponent.ets:3 |
| 无阴影层级 | 所有 shadow 都是 `radius:8` |

**修复方案**：
- 参考苹果系统色 `#007AFF` + iOS HIG 功能色
- `surface_secondary` 改为 `#F2F2F7`（与 primary `#FFFFFF` 明显区分）
- `text_secondary` 改为 `#86868B`，`text_tertiary` 改为 `#C7C7CC`（拉开层级）
- 移除 `STROKE_COLOR` 硬编码，用 `$r('app.color.canvas_stroke')`
- 引入阴影层级常量（但保持简单，不需要 ThemeConfig 类）

### 1.5 布局不自适应

| 问题 | 根因 | 文件:行 |
|------|------|---------|
| CaptureTab 无 maxWidth | 平板全宽拉伸 | Index.ets:158-253 |
| SettingsTab 始终单列 | 无响应式多列 | Index.ets:484-591 |
| Detail 内容左对齐 | `maxWidth:720` 无居中 | Detail.ets:73 |
| CaptureEditorComponent 固定高度 | `Tabs.height(280)`, `CANVAS_HEIGHT=240` | CaptureEditorComponent.ets:5,57 |
| Navigation 固定 Stack | 未用 NavigationMode.Auto/Split | Index.ets:144 |

## 二、设计方案

### 2.1 断点与布局模式（对齐官方标准）

**常量定义**（替换 Index.ets:45-46）：

```typescript
const BREAKPOINT_SM = 600;  // 官方 sm/md 分界
const BREAKPOINT_MD = 840;  // 官方 md/lg 分界
```

**三档 layoutMode**（替换当前的 compact/desktop 二档）：

| layoutMode | 条件 | 对应官方 | Navigation | Tabs | 列表列数 |
|-----------|------|---------|-----------|------|---------|
| `compact` | width < 600 | sm | Stack | 底部水平 | 1 |
| `medium` | 600 ≤ width < 840 | md | Auto(→Split) | 底部水平 | 2 |
| `desktop` | width ≥ 840 | lg | Auto(→Split) | 左侧垂直 | 2-3 |

**重要决策**：
- medium 档(600-840) Tabs 仍用底部水平（官方建议 md 仍可底部，仅 lg 才建议左侧垂直）
- desktop 档(≥840) Tabs 改为左侧垂直
- Navigation 用 `NavigationMode.Auto`（≥600vp 自动 Split）
- 保留 `onAreaChange` 检测方式，不引入 GridRow 包装

**applyDefaultMode 修改**：

```typescript
@State private hasSetDefaultType: boolean = false;

private applyDefaultMode(width: number): void {
  if (width < BREAKPOINT_SM) {
    this.layoutMode = 'compact';
  } else if (width < BREAKPOINT_MD) {
    this.layoutMode = 'medium';
  } else {
    this.layoutMode = 'desktop';
  }
  // 仅首次设置 activeType
  if (!this.hasSetDefaultType) {
    this.hasSetDefaultType = true;
    this.activeType = this.layoutMode === 'desktop' ? IdeaType.DOCUMENT : IdeaType.AUDIO;
  }
}

private deviceHint(): string {
  if (this.layoutMode === 'compact') return '手机模式';
  if (this.layoutMode === 'medium') return '平板模式';
  return '桌面模式';
}
```

### 2.3 录音 UI — 大圆钮状态驱动

替换 CaptureEditorComponent 的 `AudioEditor` Builder：

```
状态机: idle → recording → paused → (recording | idle)

idle:
  ┌──────────┐
  │    🎤    │  64vp 填充圆, brand_primary
  └──────────┘
  "点击录音"
  时长: --:--

recording:
  ┌──────────┐
  │    ❚❚   │  64vp 填充圆, brand_primary + 脉冲动画
  └──────────┘     scale 1.0→1.08 循环, opacity 1→0.7
  ┌──┐      ┌──┐
  │ ✓│ 保存  │ ✕│ 取消   36vp 小圆钮
  └──┘      └──┘
  时长: 02:34  (实时计时)

paused:
  ┌──────────┐
  │    ▶    │  64vp 描边圆, brand_primary
  └──────────┘
  ┌──┐      ┌──┐
  │ ✓│ 保存  │ ✕│ 取消
  └──┘      └──┘
  时长: 02:34 (暂停中)
```

**实现要点**：
- 主按钮 64x64vp, `borderRadius(32)`
- `audioRecorderState` 驱动:
  - `idle`: 填充圆 + 🎤 icon, `onClick → onAudioStart`
  - `recording`: 填充圆 + ❚❚ icon + `@State recordPulse: number` 动画, `onClick → onAudioPause`
  - `paused`: 描边圆(2px) + ▶ icon, `onClick → onAudioResume`
- 保存按钮: `onClick → onAudioStop`（停止即保存）
- 取消按钮: `onClick → onAudioCancel`
- 实时计时: 用 `audioDurationMs` 格式化显示 "MM:SS"
- 脉冲动画: `animateTo({duration:800, curve:Curve.EaseInOut, iterations:-1})` 控制 scale
- 移除 `Progress({value:0})`

### 2.4 CaptureEditorComponent 其他修复

1. **移除 `STROKE_COLOR = '#111827'`** → 改用 `$r('app.color.canvas_stroke')`
2. **响应式高度**：传入 `isCompact: boolean` prop
   - compact: `Tabs.height(240)`, `CANVAS_HEIGHT=200`
   - medium/desktop: `Tabs.height(320)`, `CANVAS_HEIGHT=280`
3. **默认 Tab 绑定 activeType**：Tabs 初始 index 由 activeType 决定

### 2.5 IdeaCardComponent 增强

1. **音频时长显示**：`idea.asset?.durationMs` → 格式化 "🎵 2:34"（有录音时）或 "🎤 点击录制"（无录音时）
2. **标签数量自适应**：compact 显示 2+溢出，medium 显示 3+溢出，desktop 显示 5+溢出
   - 传入 `maxTags: number` prop（compact=2, medium=3, desktop=5）
3. **来源上下文行**：有 `idea.context.title` 时在底部显示一行淡色文字
4. **手写缩略图**：暂不实现（需要图片加载，复杂度高，留后续）

### 2.6 Index.ets 响应式布局

| 区域 | compact(<600) | medium(600-840) | desktop(≥840) |
|------|-------------|----------------|--------------|
| Navigation mode | Stack | Auto(→Split) | Auto(→Split) |
| Tabs barPosition | End(底部) | End(底部) | Start(左侧) |
| Tabs vertical | false | false | true |
| CaptureTab maxWidth | 无(全宽) | 600vp 居中 | 720vp 居中 |
| LibraryTab lanes | 单列 | 2列(320-400) | 2-3列(320-480) |
| SettingsTab | 单列 | 单列 | 2列 |
| default activeType | AUDIO | AUDIO | DOCUMENT |

**关键改动**：
- Navigation `.mode(NavigationMode.Auto)` — 官方推荐，≥600vp 自动 Split
- CaptureTab: `constraintSize({maxWidth})` + 外层 `alignItems(HorizontalAlign.Center)`
- LibraryTab: `List.lanes()` 根据 layoutMode 动态
- SettingsTab: desktop 用 Row 2列

### 2.7 Detail.ets 响应式布局

- Scroll 添加 `.align(Alignment.TopCenter)` 使内容居中
- `constraintSize({maxWidth})` 根据 layoutMode 动态:
  - compact: 不限制（手机全宽）
  - medium: 720vp
  - desktop: 960vp
- 传入 `layoutMode` 或通过路由参数传递

## 五、风险与兼容

| 风险 | 缓解 |
|------|------|
