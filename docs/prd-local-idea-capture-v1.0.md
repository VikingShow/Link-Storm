# Link Storm 本地灵感捕捉产品需求文档 v1.0

文档状态：草案  
创建日期：2026-06-10  
产品方向：纯本地、多端、跨应用灵感捕捉与想法管理  
目标平台：HarmonyOS 手机、平板、PC/二合一  
暂缓范围：云服务器、账号体系、开放 AI 直接读写接口、新闻/活动推荐

## 1. 文档目的

本文定义 Link Storm 当前完整产品形态，不拆分开发阶段。

产品目标是让用户在任何场景下快速留存想法，并在本地完成管理、检索、整理、导出和后续 AI 加工预留。

重点覆盖：

1. 手机语音捕捉。
2. 平板手写捕捉。
3. PC/二合一文档捕捉。
4. 跨应用悬浮入口。
5. 当前内容来源留存：链接优先，截图兜底。
6. 本地想法管理。
7. 导出与导入。
8. 本地优先的数据安全与隐私。
9. 后续 AI 整理能力预留。

## 2. 背景与问题

用户在阅读文章、观看视频、参加会议、浏览资料、使用其他应用时，经常会产生短暂想法。

当前常见问题：

1. 想法产生时切换到笔记应用成本高。
2. 手机上打字慢，语音更自然。
3. 平板上手写和画图更自然。
4. PC/二合一上适合写成较完整文档。
5. 想法经常和某篇文章、某个视频、某个页面有关，但记录后上下文丢失。
6. 录音、手写、文字散落在不同应用里，难以统一管理。
7. 用户希望本地保存，不希望一开始依赖服务器。

Link Storm 要解决的是：

```text
我正在看东西
-> 突然有想法
-> 不离开当前上下文也能快速记录
-> 自动保存当时看见的内容线索
-> 后续能找回、整理、导出、加工
```

## 3. 产品定位

Link Storm 是一个本地优先的多端灵感捕捉与想法管理工具。

核心价值：

1. 快速捕捉：在最短路径内记录想法。
2. 上下文留存：保留想法产生时的文章、视频、截图或来源信息。
3. 多端自然输入：手机说、平板写、PC 整理。
4. 本地管理：标签、文件夹、搜索、收藏、归档。
5. 可带走：支持标准格式导出，避免数据锁死。
6. 可进化：后续可接 AI，把零散想法整理成结构化笔记、行动项和主题沉淀。

## 4. 目标用户

### 4.1 主要用户

1. 创业者：浏览信息时快速记录产品、商业和资源想法。
2. 学生/研究者：看论文、文章、视频时记录灵感和问题。
3. 产品经理/设计师：看到案例时记录评价、拆解和待办。
4. 开发者：看技术文章和视频时记录实现思路。
5. 内容创作者：把碎片灵感沉淀成选题和大纲。
6. 企业管理者：记录会议、业务判断和行动计划。

### 4.2 用户核心诉求

1. 我不想因为记录想法而打断当前阅读或观看。
2. 我希望记录方式符合设备：手机语音，平板手写，PC 文档。
3. 我希望想法自动带上当时看的内容线索。
4. 我希望所有想法都在一个地方管理。
5. 我希望数据默认在本地。
6. 我希望将来可以让 AI 帮我整理，但不能丢失原始记录。

## 6. 关键可行性判断

### 6.1 悬浮入口

需求：用户在其他应用中阅读或观看时，屏幕上存在一个小圆球或轻量入口，点击后快速开始记录。

可行性：有条件可行。

鸿蒙存在全局悬浮窗/全局闪控球相关能力，可为应用提供跨应用的全局入口。官方文档中提到“全局闪控球”是一种在设备屏幕上悬浮的非全屏应用窗口，用于提供临时全局能力和跨应用交互。

限制：

1. 全局悬浮入口通常需要较高权限或用户授权。
2. 权限申请和上架审核可能受场景限制。
3. 悬浮入口不能直接读取其他应用的页面内容。
4. 需要提供明显关闭入口，避免打扰用户。

降级方案：

1. 系统分享入口：用户点击当前应用的分享，选择 Link Storm。
2. 快捷方式/桌面卡片。
3. 通知栏快捷入口。
4. App 内全局快捷捕捉按钮。

### 6.2 自动分屏

需求：

```text
手机：点击悬浮入口后开始语音
平板：点击悬浮入口后自动分屏，打开写字板
PC/二合一：点击悬浮入口后自动分屏或侧边窗口，打开文档编辑器
```

可行性：部分可行。

鸿蒙支持多窗口、分屏、悬浮窗等形态，应用可以适配全屏、分屏、自由窗口等模式。

限制：

1. 应用通常不能无条件强制把另一个前台应用切成分屏。
2. 是否能自动进入分屏，取决于系统能力、设备形态、用户设置和权限。
3. 更稳妥的方案是打开 Link Storm 的悬浮面板、半屏面板或自由窗口，而不是强制控制其他应用窗口。

产品策略：

1. 平板优先打开右侧手写面板。
2. PC/二合一优先打开右侧文档面板。
3. 如果系统不允许自动分屏，则打开浮动小窗。
4. 如果浮动小窗不可用，则跳转到 App 内捕捉页。

### 6.3 当前链接获取

需求：用户看文章或视频时，记录想法时自动获取当前文章或视频链接。

可行性：不能保证自动获取，必须分场景。

可靠路径：

1. 用户通过系统分享把链接发送给 Link Storm。
2. 当前应用传递 URL、标题、摘要、封面图等分享数据。
3. 浏览器或内容应用支持标准分享。
4. 用户复制链接后，Link Storm 读取剪贴板需要用户明确授权或操作。

不可靠路径：

1. 悬浮球直接读取当前应用 URL。
2. 后台自动解析其他应用页面。
3. 自动读取视频 App 当前播放链接。

产品策略：

```text
链接优先来自分享
剪贴板作为手动辅助
悬浮球只负责触发捕捉，不承诺自动拿到链接
拿不到链接时提示用户选择截图或手动补充
```

### 6.4 截图兜底

需求：如果获取不到链接，则自动截图，保存当时画面。

可行性：有条件可行。

鸿蒙提供屏幕截图、组件截图和录屏相关能力。组件截图主要适合截取本应用内部 UI；屏幕截图/录屏涉及更高权限和用户授权。

限制：

1. 应用不能无授权截取其他应用屏幕。
2. 某些应用或安全页面可能禁止截图。
3. 视频、金融、隐私页面可能无法截图或只能得到空白/黑屏。
4. 截图可能包含敏感信息，必须让用户明确知道。

产品策略：

1. 获取不到链接时，弹出“保存截图作为上下文”。
2. 用户确认后再触发系统截屏/录屏授权流程。
3. 截图只作为该条想法的私有附件。
4. 用户可以删除截图。
5. 如果截图失败，允许手动输入标题或来源。

## 7. 核心用户流程

### 7.1 手机跨应用语音捕捉

```text
用户正在看文章/视频
-> 点击 Link Storm 悬浮球
-> 系统显示小型录音面板
-> 自动尝试读取分享上下文/剪贴板链接
-> 用户开始录音
-> 录音结束
-> 保存语音、时间、来源线索
-> 如果无链接，提示是否截图
-> 想法进入本地想法库
```

### 7.2 平板跨应用手写捕捉

```text
用户正在阅读资料
-> 点击 Link Storm 悬浮球
-> 右侧打开手写面板或浮动写字板
-> 自动尝试记录来源链接
-> 用户手写或画图
-> 自动保存笔迹和预览图
-> 如果无链接，提示保存截图
-> 想法进入本地想法库
```

### 7.3 PC/二合一跨应用文档捕捉

```text
用户正在看网页/视频/文档
-> 点击 Link Storm 悬浮球或快捷入口
-> 右侧打开文档面板
-> 自动插入来源标题/链接，若可用
-> 用户输入想法、清单或大纲
-> 自动保存
-> 想法进入本地想法库
```

### 7.4 App 内管理想法

```text
打开 Link Storm
-> 进入想法库
-> 按时间、标签、文件夹、类型查看
-> 搜索关键词
-> 打开想法详情
-> 查看原始语音/手写/文档
-> 查看来源链接或截图
-> 编辑标题、标签、备注
-> 导出或归档
```

### 7.5 后续 AI 整理

```text
用户积累多条想法
-> 选择一个文件夹/标签/时间范围
-> 点击整理
-> AI 生成主题摘要、行动项、问题清单
-> 保留每条原始想法引用
-> 用户可回到原始录音、手写或截图
```

## 8. 功能需求

### 8.1 跨应用捕捉入口

#### 8.1.1 悬浮球

说明：一个可拖动的小型全局入口，用于快速打开捕捉面板。

功能：

1. 支持开启/关闭。
2. 支持拖动到屏幕边缘。
3. 支持点击打开默认捕捉方式。
4. 支持长按展开模式选择。
5. 支持在全屏视频、阅读、浏览网页时呼出。
6. 支持隐藏 30 分钟、今天隐藏、永久关闭。

模式选择：

```text
录音
手写
文档
截图
保存链接
```

验收标准：

1. 用户开启后，悬浮入口在允许的应用场景中可见。
2. 用户可随时关闭。
3. 点击后能在 1 秒内打开对应捕捉面板。
4. 权限不可用时有清晰降级入口。

#### 8.1.2 分享入口

说明：用户通过其他应用的分享菜单把链接、文本或图片发送到 Link Storm。

功能：

1. 接收 URL。
2. 接收文本。
3. 接收图片。
4. 接收文件。
5. 根据分享内容创建想法。
6. 允许用户补充语音、手写或文档。

验收标准：

1. 从浏览器分享网页链接到 Link Storm 后，能生成带链接的想法。
2. 从内容 App 分享文本后，能生成带文本的想法。
3. 从相册分享图片后，能生成带图片附件的想法。

#### 8.1.3 快捷入口

说明：悬浮球不可用时的备用入口。

功能：

1. 桌面快捷方式。
2. 通知栏入口。
3. App 内快捷按钮。
4. 最近任务页快速恢复。

### 8.5 上下文留存

目标：记录想法产生时用户正在看的内容线索。

上下文类型：

```text
link
shared_text
screenshot
image
manual_note
unknown
```

字段：

```text
title
url
source_app
captured_at
screenshot_path
shared_text
manual_note
```

规则：

1. 有分享链接时，优先保存链接。
2. 有分享标题时，保存标题。
3. 无链接时，询问是否截图。
4. 截图失败时，允许用户手动输入来源说明。
5. 所有上下文都可删除。

验收标准：

1. 从分享创建的想法能打开原链接。
2. 截图上下文能在详情页查看。
3. 用户能清除上下文附件。

### 8.11 AI 整理预留

当前不要求接入 AI，但数据模型和交互应为后续预留。

后续能力：

1. 语音转文字。
2. 手写识别。
3. 截图 OCR。
4. 自动标题。
5. 自动摘要。
6. 自动标签。
7. 行动项提取。
8. 主题归类。
9. 多条想法合并整理。
10. 回链到原始记录。

核心原则：

1. AI 结果不能覆盖原始记录。
2. AI 结果必须能追溯来源。
3. 用户可以编辑 AI 结果。
4. 用户可以删除 AI 结果。

AI 整理示例：

```text
原始记录：
3 条语音、2 张手写图、1 篇文档

整理结果：
主题：视频学习时产生的产品想法
摘要：用户想做一个跨应用悬浮捕捉工具。
行动项：
1. 验证悬浮球权限。
2. 验证分享链接接收。
3. 设计截图兜底流程。
引用：
每个结论都能点回原始语音、手写或文档。
```

## 9. 非功能需求

### 9.1 本地优先

1. 无网络时核心功能可用。
2. 想法默认保存在本地。
3. 不强制登录。
4. 不强制上传。
5. 用户可导出全部数据。

### 9.2 性能

1. App 冷启动进入捕捉界面不超过 2 秒。
2. 悬浮入口点击后打开面板不超过 1 秒。
3. 录音停止后保存不超过 2 秒。
4. 列表 1000 条数据滚动保持流畅。
5. 搜索 1000 条数据不超过 1 秒。

### 9.3 稳定性

1. 录音中断时尽量保留已录内容。
2. 手写自动保存，避免误关丢失。
3. 文档编辑自动保存。
4. 导出失败时保留错误信息。
5. 导入失败不得破坏已有数据。

### 9.4 隐私与安全

1. 麦克风、截图、文件访问等权限必须按需申请。
2. 截图前必须明确告知用户。
3. 录音、截图和笔记默认私有。
4. 删除想法时可选择同时删除附件。
5. 导出包可以选择加密，后续支持。
6. 不后台监听用户行为。
7. 不自动读取其他应用内容。

### 9.5 可访问性

1. 录音按钮足够大。
2. 支持深色模式。
3. 支持字体缩放。
4. 关键操作有明确反馈。
5. 悬浮球可调整透明度和位置。

## 12. 权限需求

权限按需申请，不在首次启动一次性全部申请。

### 12.1 麦克风

场景：语音捕捉。  
触发：用户首次录音时。  
拒绝处理：提示改用文字或手写。

### 12.2 悬浮窗/全局闪控球

场景：跨应用快速入口。  
触发：用户开启悬浮入口时。  
拒绝处理：提供分享入口、通知入口和桌面快捷方式。

### 12.3 截屏/录屏

场景：无法获取链接时保存上下文截图。  
触发：用户主动点击“保存截图”。  
拒绝处理：允许用户手动输入来源说明。

### 12.4 文件访问

场景：导出、导入、选择附件。  
触发：用户主动导出或导入时。  
拒绝处理：提示无法完成文件操作。

## 13. 跨设备与同步

完整产品应支持多种迁移和同步方式，但默认不设服务器。

### 13.1 账号策略

Link Storm 本身不应在当前完整产品设计中强制自建账号系统。

原因：

1. 产品定位是本地优先。
2. 自建账号会引入服务器、登录、隐私政策、数据安全和运维成本。
3. 当前核心价值是捕捉和管理想法，不是云协作。

完整产品应支持三种身份模式：

```text
无账号模式：单设备本地使用，支持导出/导入。
系统可信设备模式：依赖 HarmonyOS/华为账号下的可信设备关系进行同步。
自建账号模式：未来如果做云同步、多平台同步或团队协作，再考虑。
```

推荐产品决策：

```text
默认无账号
不强制登录
不自建账号
跨设备同步优先使用系统可信设备能力
导出/导入作为所有场景的兜底
```

### 13.2 是否需要华为账号

结论：取决于同步方式。

不需要华为账号的情况：

```text
单设备本地使用
手动导出 ZIP
手动导入 ZIP
通过文件传输、U 盘、聊天工具、系统分享传备份包
```

可能需要华为账号或系统可信关系的情况：

```text
设备靠近后自动发现
同一用户多设备间无感同步
跨设备访问本应用数据
基于 HarmonyOS 分布式能力同步关系型数据或对象数据
```

这类体验通常依赖系统提供的设备组网、可信设备、分布式数据同步权限，实践中可能要求设备处于同一用户体系或完成可信授权。它不等于 Link Storm 要自建账号，但用户可能需要使用华为账号或系统级可信设备关系。

需要自建账号的情况：

```text
跨品牌设备云同步
公网自动同步
网页端访问
多用户协作
团队空间
换机后云端自动恢复
```

这些不属于当前产品范围。

### 13.3 同步模式总览

| 模式 | 是否自建服务器 | 是否需要 Link Storm 账号 | 是否可能依赖华为账号/系统可信关系 | 难度 | 适合场景 |
|---|---|---|---|---|---|
| 单设备本地 | 否 | 否 | 否 | 低 | 默认使用 |
| 手动导出/导入 | 否 | 否 | 否 | 低 | 备份、迁移、兜底 |
| 系统分享备份包 | 否 | 否 | 否 | 低 | 发送到另一设备 |
| HarmonyOS 同应用跨设备同步 | 否 | 否 | 是 | 中高 | 同用户多鸿蒙设备 |
| 局域网点对点同步 | 否 | 否 | 否 | 高 | 同一 Wi-Fi 下同步 |
| 自建云同步 | 是 | 是 | 否 | 高 | 未来多平台/云端能力 |

### 13.4 手动导出/导入

说明：基础能力，必须支持。

```text
设备 A 导出 ZIP
-> 通过系统分享或文件传输发送到设备 B
-> 设备 B 导入
-> 合并本地想法库
```

要求：

1. 导出包包含数据库元数据和附件。
2. 导出包可选择是否加密。
3. 导入前显示包内数量和来源设备。
4. 导入时按 ID、更新时间、hash 合并。
5. 导入失败不得破坏已有数据。

### 13.5 HarmonyOS 同应用跨设备同步

说明：后续验证能力。

产品目标：

```text
同一用户的手机、平板、PC/二合一之间
在系统可信关系存在时
同步想法元数据和必要附件
不经过 Link Storm 自建服务器
```

适合同步：

1. 标题。
2. 标签。
3. 文件夹。
4. 文本。
5. 小型元数据。

大文件：

1. 音频。
2. 截图。
3. 手写预览图。

大文件建议按需传输，避免一次性同步失败。

前提条件：

1. 设备均安装 Link Storm。
2. 设备满足 HarmonyOS 分布式能力要求。
3. 用户授予分布式数据同步相关权限。
4. 设备之间建立可信关系。
5. 实际是否要求同一华为账号，以系统能力和官方要求为准。

产品交互：

```text
设置 -> 跨设备同步
-> 查看附近/可信设备
-> 选择设备
-> 确认同步范围
-> 同步元数据
-> 按需同步附件
-> 显示同步结果和冲突
```

同步范围：

```text
仅元数据
元数据 + 文本文档
元数据 + 小附件
全部数据
指定文件夹/标签
```

限制：

1. 不承诺所有设备都能无感同步。
2. 不承诺后台长期自动同步。
3. 不承诺大音频和大量截图实时同步。
4. 必须有手动导出/导入兜底。

### 13.6 局域网点对点同步

说明：高级能力。

流程：

```text
同一局域网
-> 扫码配对
-> 建立加密连接
-> 比较数据版本
-> 传输差异
-> 处理冲突
```

不作为完整产品的基础依赖，但可作为后续增强方向。

局域网同步不依赖华为账号，但需要自己处理：

1. 设备发现。
2. 扫码配对。
3. 端到端加密。
4. 身份校验。
5. 差异同步。
6. 大文件断点续传。
7. 冲突合并。
8. 失败重试。

### 13.7 靠近即同步

说明：理想体验，但不作为基础能力。

产品设想：

```text
手机靠近平板或 PC
-> 系统识别可信设备
-> Link Storm 显示同步提示
-> 用户确认
-> 同步最近想法
```

限制：

1. 需要设备发现能力。
2. 需要可信设备关系。
3. 需要权限授权。
4. 需要处理断连和冲突。
5. 如果不依赖系统分布式能力，自研成本高。

### 13.8 冲突处理

规则：

1. 每条想法使用全局唯一 ID。
2. 每条想法记录 device_id、updated_at、version。
3. 新增直接合并。
4. 删除使用软删除。
5. 同一字段冲突时生成副本或提示用户选择。
6. 附件按 hash 去重。

冲突示例：

```text
同一条文档想法在手机和平板都被修改
-> 系统保留两个版本
-> 标记为冲突
-> 用户可选择合并、保留手机版本、保留平板版本
```

### 13.9 同步状态

每条想法需要记录同步状态：

```text
local_only
pending_sync
synced
conflict
sync_failed
```

每个附件需要记录：

```text
local_only
pending_transfer
available_on_device
missing_asset
transfer_failed
```

### 13.10 产品决策

完整产品应明确传达：

1. Link Storm 不要求登录才能使用。
2. 用户数据默认只保存在本机。
3. 导出/导入是基础同步和备份方式。
4. 如果用户开启 HarmonyOS 跨设备同步，可能需要系统账号、可信设备和权限授权。
5. Link Storm 不自建服务器时，不能提供跨公网云同步。
6. 未来若增加云同步，需要单独设计账号、加密、隐私和付费策略。

## 14. 交互原则

1. 记录比整理更优先。
2. 不强迫用户填写标题。
3. 不强迫用户选择标签。
4. 上下文能自动带就自动带，不能自动带就允许补充。
5. AI 只能增强，不得破坏原始记录。
6. 所有隐私敏感操作都要明确提示。
7. 悬浮入口要克制，不能影响用户看内容。

## 15. 风险与约束

### 15.1 悬浮入口权限风险

风险：权限不可用、审核不通过或用户拒绝授权。  
应对：提供分享入口、桌面快捷方式、通知入口。

### 15.2 链接获取不可控

风险：其他应用不提供链接或分享内容。  
应对：分享优先，截图兜底，手动补充。

### 15.3 截图权限和内容限制

风险：用户拒绝授权，或目标应用禁止截图。  
应对：手动来源说明，允许仅保存想法。

### 15.4 跨应用误触和打扰

风险：悬浮球影响阅读或视频观看。  
应对：透明度、贴边、临时隐藏、黑名单应用。

### 15.5 数据丢失

风险：录音、手写、文档未保存。  
应对：自动保存、临时草稿、崩溃恢复、定期备份提醒。

### 15.6 AI 加工可信度

风险：AI 总结错误或丢失语义。  
应对：保留原始记录，AI 结果可编辑，可回链。

## 17. 验收总则

一个完整版本应满足：

1. 用户能在手机上用语音快速记录想法。
2. 用户能在平板上用手写快速记录想法。
3. 用户能在 PC/二合一上用文档记录想法。
4. 用户能通过悬浮入口或降级入口在跨应用场景中捕捉想法。
5. 用户能保存当前内容链接；获取不到链接时，可保存截图或手动备注。
6. 所有想法都进入本地想法库。
7. 用户能搜索、标签、文件夹、收藏、归档。
8. 用户能导出和导入自己的数据。
9. 无网络状态下核心记录和管理功能可用。
10. AI 加工结果必须能回到原始记录。
