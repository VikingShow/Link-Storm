# LinkStorm UI 简化与自适应重构设计方案

## 一、设计原则

1. **核心定位**：灵感捕捉 → 组织管理 → 回顾检索，本地优先
2. **简洁至上**：每个页面只做一件事，每个按钮都有存在的理由
3. **渐进揭示**：不把所有选项一次呈现，高级功能通过交互展开
4. **设备适配**：手机紧凑高效，平板信息密度适中，PC/2in1 充分利用宽屏

## 二、功能删减决策（基于用户确认）

| 功能 | 决策 | 理由 |
|------|------|------|
| AI 整理区域 | **移除**（当前分支保留，新分支去掉） | 非真实AI，只是手动录入，保留原味记录 |
| 同步状态UI（徽章/标记/筛选） | **移除** | 云同步未实现，手动标记对用户无意义 |
| 加密备份UI | **移除** | 高级功能，MVP只需基础备份 |
| 6个独立导出按钮 | **合并为1个下拉选择** | 一个"导出/备份"按钮 + 下拉菜单选择格式 |
| 截图兜底 | **移除** | 开发者兜底方案，非用户功能 |
| 手写JSON导出/预览图导出 | **移除** | 小众功能 |
| 附件管理6个按钮 | **简化为2个** | 只保留"更换附件"+"移除附件" |
| 捕捉页6个元数据输入 | **两步流程** | 第一步只捕捉内容，第二步补元数据 |
| 批量操作 | **保留** | 用户确认保留 |
| 悬浮球 | **保留** | 快速捕捉入口 |

## 三、页面级设计方案

### 3.1 捕捉页（Capture）— 两步流程

**核心思想**：先捕获内容，再补充上下文。减少初始认知负荷。

#### 第一步：快速捕捉

```
┌────────────────────────┐
│ Navigation 标题栏       │
│ "记录灵感"              │
├─────────────────────────┤
│                         │
│  ┌─ 模式切换 Tabs ────┐ │
│  │ 📝文字  🎤语音  ✏️手写│ │
│  └────────────────────┘ │
│                         │
│  [内容区域]             │
│  文字: TextArea         │
│  语音: 大录音按钮+时长  │
│  手写: Canvas画板       │
│                         │
│  ┌─ 备注 (可选) ──────┐ │
│  │ 补充备注...         │ │
│  └───────────────────┘ │
│                         │
│  ┌───────────────────┐ │
│  │    ✦ 保存灵感       │ │
│  └───────────────────┘ │
│                         │
└─────────────────────────┘
```

**元素计数**：1 模式切换 + 1 内容区 + 1 备注(可选) + 1 保存按钮 = **4 个核心交互**

**关键简化**：
- 移除标题/标签/来源/文件夹等元数据输入
- 语音模式：单一大按钮（圆形），点击切换录音/停止，暂停为次要操作
- 手写模式：画板 + 撤销按钮，移除"保存预览"（自动保存）
- 备注区折叠，点击展开

#### 第二步：保存后补全（Bottom Sheet / Dialog）

保存后自动弹出轻量级补全面板：

```
┌────────────────────────┐
│  给这条灵感加点信息     │
├────────────────────────┤
│  标题: [自动生成/可编辑] │
│  标签: [逗号分隔]       │
│  标签快选: [chip] [chip] │
│  文件夹: [下拉选择]     │
│                         │
│  来源标题: [可选]       │
│  来源链接: [可选]       │
│  📋 读取剪贴板          │
│                         │
│  [跳过]       [完成]    │
└────────────────────────┘
```

**元素计数**：5 输入 + 标签快选 + 2 按钮 = **~8 个交互**（但用户可跳过全部）

**关键设计**：
- 标题自动从内容前20字生成
- 标签快选展示最近使用的5个标签
- "跳过"按钮明显，允许零元数据保存
- 来源区默认折叠，"添加来源"展开

### 3.2 想法库页（Library）— 简化筛选

**核心思想**：搜索 + 类型切换 即可满足90%场景，高级筛选按需展开。

```
┌─────────────────────────┐
│ Navigation              │
├────────────────────────┤
│ 🔍 搜索框              │
│                         │
│ [全部] [文字] [语音] [手写]  ← 类型切换，常驻 │
│                         │
│ ┌─── 筛选栏(可展开) ──┐ │
│ │ 📁文件夹  🏷️标签    │ │ ← 点击展开选择
│ │ 收藏  归档          │ │
│ └───────────────────┘ │
│                         │
│ ┌─────────────────────┐ │
│ │ 想法卡片            │ │
│ │ 标题 · 类型 · 时间  │ │
│ │ 预览文本(1行)       │ │
│ │ ♡     [2个标签]     │ │
│ └─────────────────────┘ │
│ ┌────────────────────┐ │
│ │ ...更多卡片         │ │
│ └─────────────────────┘ │
│                         │
│ (选中时: 批量操作栏)   │
└────────────────────────┘
```

**筛选简化**：
- 移除 8 个同步状态芯片
- 移除独立的"全部状态"芯片行
- 类型切换常驻（4个选项），收藏/归档+文件夹+标签 可展开
- 展开区域使用 Bottom Sheet 或内联展开，不占常驻空间

**卡片简化**（IdeaCardComponent 重设计）：

```
┌────────────────────────────┐
│ 📄 3分钟前           ♡     │ ← 类型图标+相对时间+收藏
│ 标题文字(最多2行)           │
│ 预览文本(1行，灰色)        │
│ [标签1] [标签2] +3         │ ← 最多显示2个标签+溢出
└────────────────────────────┘
```

**移除项**：同步状态徽章、来源上下文行、归档按钮（长按/滑动操作替代）
**保留项**：类型图标、时间、收藏心形、标题、预览、标签
**交互**：点击打开详情、左滑删除、长按多选

### 3.3 详情页（Detail）— 2个折叠区

**核心思想**：主内容直接可编辑，次要信息折叠。

```
┌────────────────────────┐
│ Navigation ← 返回       │
├────────────────────────┤
│                         │
│ 标题 [可编辑]           │ ← 直接编辑，非折叠
│ 标签 [可编辑] + 标签快选│
│ 正文 [可编辑]           │
│ 备注 [可编辑]           │
│                         │
│ ▼ 来源与附件            │ ← 折叠区1
│   来源标题/链接         │
│   手写预览/音频播放器   │
│   更换附件 | 移除附件   │
│                         │
│ ▼ 文件夹与分类          │ ← 折叠区2
│   文件夹选择            │
│   创建时间/更新时间     │
│                         │
├────────────────────────┤
│ ♡ 收藏  📦归档  🗑删除  │ ← 底部操作栏
└────────────────────────┘
```

**移除项**：
- AI 整理区域（整个折叠区）
- 手动同步状态标记（标记本机/标记已同步）
- 6个附件按钮 → 只保留2个（更换+移除）
- 手写JSON导出、预览图导出
- 独立的"来源上下文"折叠区 → 合并到"来源与附件"

**保留项**：
- 标题/标签/正文/备注 直接可编辑
- 来源与附件折叠区
- 文件夹与分类折叠区
- 底部 收藏/归档/删除

### 3.4 设置页（Settings）— 极简

```
┌────────────────────────┐
│ Navigation              │
├────────────────────────┤
│                         │
│ ── 权限 ──              │
│ 🎤 麦克风    [重试]     │
│ ⚡ 悬浮球    [开关]     │
│                         │
│ ── 数据 ──              │
│ 📤 导出与备份  [▼]     │ ← 下拉选择格式
│   ├ 导出 JSON           │
│   ├ 导出 Markdown       │
│   ├ 导出纯文本          │
│   ├ ZIP 完整备份        │
│   └ 分享...             │
│ 📥 导入数据             │
│                         │
│ ── 管理 ──              │
│ 📁 文件夹管理           │ ← 展开面板
│ 🏷️ 标签管理            │ ← 展开面板
│                         │
└────────────────────────┘
```

**移除项**：
- 6个独立导出按钮 → 1个下拉选择
- 加密备份开关+密码框
- 截图兜底
- 分享文本/分享Markdown 独立按钮（合并到下拉）

**保留项**：
- 麦克风权限+悬浮球开关
- 统一的导出/备份入口
- 导入入口
- 文件夹管理（展开式）
- 标签管理（展开式）

## 四、设备适配方案

### 4.1 手机（< 680vp, compact 模式）

| 区域 | 适配 |
|------|------|
| 底部 Tab 栏 | 3个图标+文字，BarPosition.End |
| 捕捉页 | 全屏内容区，备注折叠 |
| 想法库 | 单列列表，筛选栏可展开 |
| 详情页 | 全屏滚动，底部操作栏固定 |
| 设置页 | 单列，文件夹/标签管理展开面板 |
| 卡片 | 紧凑模式：预览1行，标签最多2个 |

### 4.2 平板（680-1100vp, medium 模式）

| 区域 | 适配 |
|------|------|
| 侧边 Tab 栏 | 图标+文字，BarPosition.Start |
| 捕捉页 | 内容区居中，maxWidth 600vp |
| 想法库 | 双列列表（List lanes），筛选栏常驻 |
| 详情页 | 居中 maxWidth 720vp |
| 设置页 | 双列：左列权限+数据，右列管理 |
| 卡片 | 标准模式：预览2行，标签最多3个 |

### 4.3 PC/2in1（≥ 1100vp, desktop 模式）

| 区域 | 适配 |
|------|------|
| 侧边 Tab 栏 | 图标+文字，Navigation 侧栏模式 |
| 想法库 | 3列网格，筛选面板左侧常驻 |
| 详情页 | 右侧面板展示（Navigation 双栏模式） |
| 设置页 | 三列布局 |
| 卡片 | 宽松模式：预览2行，标签5个 |

**Navigation 双栏模式关键设计**：
- desktop 模式下，想法库列表在左侧占 40%，详情在右侧占 60%
- 选中想法时右侧显示详情，未选中时显示空状态提示
- 使用 `Navigation.mode(NavigationMode.Split)` 实现

### 4.4 语音录制按钮适配

| 设备 | 录音UI |
|------|--------|
| 手机 | 大圆形按钮（80vp），居中，点击录音/停止，暂停按钮在下方 |
| 平板 | 同手机，但画布更大 |
| PC | 圆形按钮+快捷键提示 |

## 八、风险与兼容

| 风险 | 缓解 |
|------|------|
| 移除 AI 区域后 IdeaAiOutput 模型仍存在 | 保留 model 定义，仅移除 UI 入口，不删除 repository 方法 |
| Navigation 双栏模式需要 API 10+ | 当前项目 minAPI 已满足 |
| BottomSheet 组件需要 API 11+ | 若不可用，降级为 AlertDialog 弹窗 |
| ExportDropdown 使用 BindMenu 需 API 10+ | 降级为 Select 组件 |
| 移除同步UI后 syncStatus 字段仍在模型中 | 保留字段，只是不展示给用户 |

## 九、回滚方案

```bash
# 回到 feature/ui-redesign 分支
git checkout feature/ui-redesign
# 删除简化分支
git branch -D feature/ui-simplify
```

所有改动在新分支上进行，不影响现有 feature/ui-redesign 分支。
